# 37. 月別・年別支出集計機能実装まとめ

## これは何のドキュメント？

[GitHub issue #34](https://github.com/t161121t/sharewallet/issues/34) への対応記録です。`GET /api/dashboard/summary` が「今月」固定だった集計を、任意の月を指定できるようにし、さらに直近数ヶ月の推移をグラフで見られるようにしました。

---

## まず結論（今回できたこと）

- `GET /api/dashboard/summary` に `?year=&month=` を追加し、任意の月の集計を取得できるようにした(省略時は従来通り今月)
- 新規 `GET /api/dashboard/summary/trend?months=6` で直近Nヶ月の個人支出合計の推移を取得できるようにした
- ホーム画面(`dashboard/page.tsx`)に「‹ 今月 ›」の月送りナビゲーションと、「推移」タブ(棒グラフ)を追加した
- 集計ロジックを `src/lib/dashboardAggregation.ts` に純粋関数として切り出し、Prismaをモックせずにユニットテストできるようにした(13件)

```bash
npx tsc --noEmit   # 型エラーなし
npx vitest run     # Test Files 5 passed / Tests 49 passed
```

---

## 背景 — なぜこの変更が必要だったか

`src/app/api/dashboard/summary/route.ts` は常に「今月」の集計しか返さず、先月以前の支出やジャンル別内訳を振り返る手段がありませんでした。家計簿アプリとして「先月と比べてどうだったか」「最近増えてきているか」を見られないのは大きな機能欠落でした。

---

## 目的

### 主目的

1. 過去の任意の月を集計して見られるようにする
2. 直近の月別推移をグラフで一目で把握できるようにする
3. 既存の集計ロジック(グループ別・カテゴリ別の合計計算)をテスト可能にする

### あえてやらなかったこと

| やらなかったこと | 理由 |
| --- | --- |
| 支出のフィルタリング機能(期間・カテゴリ・メンバー) | issue #33の別スコープ。今回はホーム画面の集計月切り替えのみ |
| ページコンポーネントのカスタムフック分割 | issue #27の別スコープ。今回は既存の `dashboard/page.tsx` の構造はそのまま拡張 |
| 年単位(12ヶ月超)の長期推移や複数年比較 | まずは直近6ヶ月(最大12ヶ月まで拡張可能なAPI設計)の表示から始め、必要になれば拡張する |

---

## 何を実装したか

### 1. `src/lib/dashboardAggregation.ts`(新規) — 集計ロジックの切り出し

`normalizeCategory`(既存route内にあったもの)に加えて、以下を純粋関数として実装:

- `getMonthRange(year, month)`: 指定年月の月初〜翌月初の範囲
- `getPreviousMonth(year, month)`: 年をまたぐ場合も正しく1ヶ月前を計算
- `getRecentMonths(base, count)`: 基準月から遡ってN件の年月を古い順で返す(推移グラフ用)
- `aggregateByGroupAndCategory(expenses)`: グループ別・カテゴリ別の合計計算(既存route内のロジックをそのまま関数化)
- `bucketMonthlyTotals(expenses, months)`: 複数月にまたがる支出一覧を月ごとの合計配列にバケット分け(推移グラフ用)

`settlement.ts`/`settlement.test.ts`(精算ロジック)と同じ考え方で、DBアクセスを伴わない計算部分だけを切り出すことで、Prismaをモックしなくてもロジックのユニットテストが書けるようにしました。

### 2. `GET /api/dashboard/summary` の拡張

```ts
const yearParam = req.nextUrl.searchParams.get("year");
const monthParam = req.nextUrl.searchParams.get("month");
// 省略時は現在の年月をデフォルトにする(既存の挙動を維持)
```

`year`/`month`が指定されていればその月を、省略されていれば従来通り今月を集計します。前月比較(`previousMonthTotalPersonalAmount`)も「指定した月の1つ前」を計算するよう一般化しました。`period.label`は今月なら従来通り「今月」、それ以外は「2026年3月」のような表記にしています。

### 3. `GET /api/dashboard/summary/trend`(新規)

直近Nヶ月(デフォルト6、最大12)の個人支出合計を配列で返す専用エンドポイントです。

```ts
export type MonthlyTrendPoint = { year: number; month: number; label: string; totalPersonalAmount: number };
export type MonthlyTrendResult = { points: MonthlyTrendPoint[] };
```

既存の`DashboardSummary`型にフィールドを追加するのではなく、別エンドポイント・別型として切り出しました(理由は後述)。

### 4. `src/components/ui/MonthlyTrendChart.tsx`(新規)

`ExpensePieChart.tsx`と同じrecharts(既存依存)を使い、シンプルな棒グラフで月別推移を表示します。

### 5. `dashboard/page.tsx` のUI追加

- タブを3つ(全体/グループ/ジャンル)から4つ(+推移)に拡張
- 「‹ 今月 › 」の月送りボタンを追加。前月ボタンは無制限に遡れますが、次月ボタンは今月より先には進めないようにしています(未来の月を見ても意味がないため)

## よくある質問

### Q. なぜ`DashboardSummary`に`monthlyTrend`フィールドを追加せず別エンドポイントにしたの？

`GET /api/dashboard/summary`は「1つの月のスナップショット」を返す責務、`GET /api/dashboard/summary/trend`は「複数月にまたがる時系列」を返す責務、と分けた方が単一責任になり、それぞれ独立してキャッシュ・呼び出し頻度を変えられるためです。また月送りのたびに毎回6ヶ月分の推移データまで再取得する必要がなくなり、無駄なDBアクセスも減らせます。

### Q. 次の月には進めない(ボタンが無効化される)のはなぜ？

未来の月には支出データが存在しないため、進めても「データなし」の空表示になるだけで意味がありません。UXとして無効化しておくのが親切と判断しました。
