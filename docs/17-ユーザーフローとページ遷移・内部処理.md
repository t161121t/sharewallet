# 17. ユーザーフローとページ遷移・内部処理

このドキュメントは、ShareWallet の「ユーザーがどの順序で画面を使うか」と「そのとき裏側で何が動くか」をまとめたものです。  
実装コードベース（`src/app` / `src/lib/apiClient.ts` / `src/app/api`）に合わせて整理しています。

---

## 1. 全体の遷移マップ

```text
/
└─ スプラッシュ（約2.9秒） -> /home

/home
├─ ログイン -> /login
└─ 新規登録 -> /register

/login
├─ 成功 -> /dashboard
└─ redirect クエリ付きの場合 -> 指定先（例: /invite/:token）

/register
├─ 成功 -> /login
└─ redirect クエリあり -> /login?redirect=...

/dashboard（BottomNav）
├─ /expense（入力）
├─ /expense/history（履歴）
├─ /profile（マイページ）
└─ /groups/new（グループ作成）

/expense/history
└─ /groups/:groupId/settlement（精算結果）

/groups/:groupId/settings
├─ 招待リンク作成・無効化
├─ メンバー直接追加/除外
└─ グループ更新/削除

/invite/:token
├─ 未ログイン -> /login?redirect=/invite/:token
└─ 参加成功 -> /dashboard
```

---

## 2. 画面ごとの役割と裏側

## 2.1 スプラッシュ ` / `

- 役割
  - ブランド演出（ロゴアニメーション、パーティクル）
  - 入口画面からホームへ遷移
- 画面遷移
  - 2.3秒でフェードアウト
  - 2.9秒で `router.push("/home")`
- API通信
  - なし

## 2.2 ホーム ` /home `

- 役割
  - 非認証ユーザー向けの分岐点
- 画面遷移
  - 「ログイン」 -> `/login`
  - 「新規登録」 -> `/register`
- API通信
  - なし

## 2.3 ログイン ` /login `

- 役割
  - メール/パスワード認証
- 入力検証
  - email / password の空チェック
- API通信
  - `POST /api/auth/login`
- 成功時の内部処理（`apiClient.login`）
  - `localStorage["sharewallet_token"]` に JWT 保存
  - `localStorage["sharewallet_user"]` にユーザー情報保存
- 遷移
  - `redirect` クエリがあればそちらへ
  - なければ `/dashboard`

## 2.4 新規登録 ` /register `

- 役割
  - ユーザー作成
- API通信
  - `POST /api/auth/register`
- 遷移
  - 成功後 `toast` 表示して `/login` へ
  - `redirect` クエリ付きなら `/login?redirect=...`

## 2.5 ダッシュボード ` /dashboard `

- 役割
  - 認証後ホーム、今月サマリー表示
- 認証ガード
  - `isAuthenticated()` が false なら `/login` へ
- 初期ロード時のAPI通信
  - `GET /api/groups`
  - `GET /api/dashboard/summary`
- タブ表示
  - `overview`（全体）
  - `groups`（グループ別）
  - `categories`（カテゴリ別）
- 主要導線
  - `+ グループ作成` -> `/groups/new`
  - BottomNav で `入力` / `詳細` / `マイページ` へ

## 2.6 支出入力 ` /expense `

- 役割
  - 支出登録（カテゴリ、金額、配分比率）
- 認証ガード
  - 未認証は `/login` へ
- 初期ロード
  - `GET /api/groups`
  - 選択グループは `localStorage["sharewallet_selected_group_id"]` を優先
  - グループ確定後
    - `GET /api/groups/:groupId`
    - `GET /api/groups/:groupId/expenses`
- 入力処理
  - カテゴリ名正規化（例: 交通費 -> 交通）
  - 金額は数値化（円）
  - 配分比率合計が 100 でなければ登録不可
- 登録時API
  - `POST /api/groups/:groupId/expenses`
- 登録成功後
  - 先頭に反映して円グラフ再計算
  - `toast` 表示

## 2.7 履歴 ` /expense/history `

- 役割
  - 日付グルーピング表示、編集・削除、精算画面への導線
- 認証ガード
  - 未認証は `/login`
  - 選択グループ未設定なら `/dashboard`
- 初期ロード
  - `GET /api/groups/:groupId`
  - `GET /api/groups/:groupId/expenses`
  - `GET /api/users/me`
- 権限判定
  - OWNER/ADMIN は全件編集削除可能
  - MEMBER は自分の支出のみ編集削除可能
- 編集API
  - `PUT /api/groups/:groupId/expenses/:expenseId`
- 削除API
  - `DELETE /api/groups/:groupId/expenses/:expenseId`
- 遷移
  - 「精算を確認」 -> `/groups/:groupId/settlement`

## 2.8 精算 ` /groups/:groupId/settlement `

- 役割
  - グループの精算結果（誰が誰にいくら払うか）表示
- 初期ロード
  - `GET /api/groups/:groupId`
  - `GET /api/groups/:groupId/settlement`
- 表示内容
  - 総支出、件数、メンバー数
  - 送金トランザクション一覧
  - メンバー別残高（+受取 / -支払）

## 2.9 グループ作成 ` /groups/new `

- 役割
  - 新規グループ作成
- 入力
  - グループ名、色、アイコン（任意）
  - アイコンはクライアントで 200x200 に加工し Data URL 化
- API通信
  - `POST /api/groups`
- 成功時
  - `localStorage["sharewallet_selected_group_id"]` 更新
  - `/dashboard` へ遷移

## 2.10 グループ設定 ` /groups/:groupId/settings `

- 役割
  - グループ情報編集、メンバー管理、招待リンク管理
- 初期ロード
  - `GET /api/groups/:groupId`
  - `GET /api/groups/:groupId/invitations`
- 主な操作とAPI
  - グループ更新: `PUT /api/groups/:groupId`
  - グループ削除: `DELETE /api/groups/:groupId`
  - メンバー追加: `POST /api/groups/:groupId/members`
  - メンバー除外: `DELETE /api/groups/:groupId/members/:userId`
  - 招待リンク作成: `POST /api/groups/:groupId/invitations`
  - 招待リンク無効化: `DELETE /api/groups/:groupId/invitations/:invitationId`

## 2.11 招待参加 ` /invite/:token `

- 役割
  - 招待リンク経由でグループ参加
- 初期ロード
  - `GET /api/invite/:token`（有効/無効/期限切れ判定）
- 参加処理
  - 未ログインなら `/login?redirect=/invite/:token`
  - ログイン後 `POST /api/invite/:token/accept`
  - 成功後 `/dashboard`

## 2.12 マイページ ` /profile `

- 役割
  - プロフィール編集、アバター更新、ログアウト
- 認証ガード
  - 未認証は `/login`
- 初期ロード
  - 先に `localStorage["sharewallet_user"]` を表示（即時表示）
  - その後 `GET /api/users/me` で最新化
- 更新API
  - `PUT /api/users/me`
- ログアウト
  - `token` / `cached user` / `selected group id` を全削除
  - `/home` へ遷移

---

## 3. BottomNav 導線（ログイン後）

BottomNav は下記4画面を固定導線として提供します。

- ホーム -> `/dashboard`
- 入力 -> `/expense`
- 詳細 -> `/expense/history`
- マイページ -> `/profile`

`profile` アイコンは `localStorage["sharewallet_user"]` の内容（名前・色・画像）を参照して表示します。

## 4. 裏側の共通処理（`src/lib/apiClient.ts`）

## 4.1 トークン付与

- `apiFetch()` が共通fetch
- `localStorage["sharewallet_token"]` があれば全リクエストに
  - `Authorization: Bearer <token>`
  を自動付与

## 4.2 共通エラー化

- 非 2xx は `ApiClientError(status, message)` を throw
- 各ページはこれを受けてトースト表示

## 4.3 ローカルストレージ設計

- `sharewallet_token`: JWT
- `sharewallet_user`: ユーザーキャッシュ
- `sharewallet_selected_group_id`: 入力対象グループ

## 5. 代表ユーザーシナリオ（時系列）

## シナリオA: 初めて使うユーザー

1. `/` -> `/home`
2. `/register` で登録
3. `/login` で認証（token保存）
4. `/dashboard` 到達
5. `/groups/new` でグループ作成
6. `/expense` で支出登録
7. `/expense/history` で履歴確認
8. `/groups/:groupId/settlement` で精算確認

## シナリオB: 招待リンク参加ユーザー

1. `/invite/:token` へ直接アクセス
2. 未ログインなら `/login?redirect=/invite/:token`
3. ログイン後、同招待ページへ戻る
4. 「参加する」で `POST /api/invite/:token/accept`
5. `/dashboard` へ遷移し、以後通常フロー

## シナリオC: 日常利用ユーザー

1. `/login` -> `/dashboard`
2. BottomNav から `/expense` で支出登録
3. `/expense/history` で編集/削除
4. 必要時 `/profile` でプロフィール更新

---

## 6. 認証・権限の要点（画面から見た挙動）

- 多くの認証必須ページはクライアント側で `isAuthenticated()` を確認し、未認証なら `/login` へリダイレクト
- API側では `requireAuthUserId` により JWT 検証
- グループ系は `assertGroupMember` / `assertGroupRole` で認可
- 履歴画面の編集UIはクライアント側でも表示制御するが、最終的な権限判定は API 側で実施

---

## 7. 既知の注意点（ユーザーフロー観点）

- 認証ガードは現在ページごとの実装で、`middleware.ts` での一元化は未対応
- token は `localStorage` 保存のため、セキュリティ強化時は Cookie 化の検討余地あり
- 招待URLの `baseUrl` はリクエスト `origin` に依存するため、環境によって生成URLが変わる

## 9. API 入力 / 出力（主要フロー抜粋）

以下はユーザーフローで頻出する API の入力と出力を、実装ベースで簡潔にまとめたものです。  
（詳細は `07-API仕様書.md` を参照）

## 9.1 認証

### `POST /api/auth/register`

- 入力（JSON）
  - `name: string`
  - `email: string`
  - `password: string`
- 成功出力（`200`）
  - `user: { id, name, email, color }`
- 代表エラー
  - `400`: 必須項目不足
  - `409`: メール重複

### `POST /api/auth/login`

- 入力（JSON）
  - `email: string`
  - `password: string`
- 成功出力（`200`）
  - `token: string`
  - `user: { id, name, email, color, avatarUrl? }`
- クライアント側副作用
  - `sharewallet_token` と `sharewallet_user` を localStorage に保存
- 代表エラー
  - `400`: 入力不備
  - `401`: 認証失敗

## 9.2 ユーザー

### `GET /api/users/me`

- 入力
  - ヘッダー: `Authorization: Bearer <token>`
- 成功出力（`200`）
  - `UserProfile`（`id`, `name`, `email`, `color`, `avatarUrl?`）
- 代表エラー
  - `401`: 未認証
  - `404`: ユーザー未存在

### `PUT /api/users/me`

- 入力（JSON, 部分更新）
  - `name?: string`
  - `email?: string`
  - `color?: string`
  - `avatarUrl?: string | undefined`
- 成功出力（`200`）
  - 更新後 `UserProfile`
- クライアント側副作用
  - `sharewallet_user` を更新

## 9.3 グループ

### `GET /api/groups`

- 入力
  - ヘッダー: `Authorization: Bearer <token>`
- 成功出力（`200`）
  - `Group[]`
  - 各 `Group`: `id`, `name`, `color`, `iconUrl?`, `members[]`

### `POST /api/groups`

- 入力（JSON）
  - `name: string`（必須）
  - `color?: string`（未指定時デフォルト）
  - `iconUrl?: string`
- 成功出力（`201`）
  - 作成した `Group`
- 副作用
  - 作成者を `OWNER` として `group_members` に追加

### `GET /api/groups/:groupId`

- 入力
  - パス: `groupId`
  - 認証必須（グループ所属必須）
- 成功出力（`200`）
  - `Group`
- 代表エラー
  - `403`: 非メンバー
  - `404`: グループ未存在

### `PUT /api/groups/:groupId`

- 入力（JSON, 部分更新）
  - `name?: string`
  - `color?: string`（HEX）
  - `iconUrl?: string | null`
- 成功出力（`200`）
  - 更新後 `Group`
- 権限
  - `OWNER` または `ADMIN`

### `DELETE /api/groups/:groupId`

- 入力
  - パス: `groupId`
- 成功出力（`200`）
  - `{ ok: true }`
- 権限
  - `OWNER` のみ

## 9.4 メンバー管理

### `POST /api/groups/:groupId/members`

- 入力（JSON）
  - `email: string`（追加対象）
- 成功出力（`201`）
  - `{ id, name, color, role }`
- 権限
  - `OWNER` / `ADMIN`

### `DELETE /api/groups/:groupId/members/:userId`

- 入力
  - パス: `groupId`, `userId`
- 成功出力（`200`）
  - `{ ok: true }`
- 権限
  - 自分の脱退、または `OWNER` / `ADMIN` による除外

## 9.5 支出

### `GET /api/groups/:groupId/expenses`

- 入力
  - パス: `groupId`
- 成功出力（`200`）
  - `ExpenseRecord[]`
  - 各 `ExpenseRecord`: `id`, `category`, `amount`, `memberId`, `memberName`, `memo?`, `date`, `shares?[]`

### `POST /api/groups/:groupId/expenses`

- 入力（JSON）
  - `category: CategoryName`
  - `amount: number`
  - `memberId?: string`（未指定時は自分）
  - `memo?: string`
  - `shares?: { userId: string; percent: number }[]`
- 成功出力（`201`）
  - 作成した `ExpenseRecord`
- バリデーション
  - `shares` 合計 100%
  - `shares` の userId はグループメンバーのみ
  - `memberId` もグループメンバーであること

### `PUT /api/groups/:groupId/expenses/:expenseId`

- 入力（JSON, 部分更新）
  - `category?: CategoryName`
  - `amount?: number`
  - `memberId?: string`
  - `memo?: string`
  - `shares?: { userId: string; percent: number }[]`
- 成功出力（`200`）
  - 更新後 `ExpenseRecord`
- 権限
  - 支出作成者本人、または `OWNER` / `ADMIN`

### `DELETE /api/groups/:groupId/expenses/:expenseId`

- 入力
  - パス: `groupId`, `expenseId`
- 成功出力（`200`）
  - `{ ok: true }`
- 権限
  - 支出作成者本人、または `OWNER` / `ADMIN`

## 9.6 ダッシュボード・精算

### `GET /api/dashboard/summary`

- 入力
  - 認証ヘッダー（Bearer）
- 成功出力（`200`）
  - `DashboardSummary`
  - 主要項目:
    - `totalPersonalAmount`
    - `previousMonthTotalPersonalAmount`
    - `byGroup[]`
    - `byCategory[]`
    - `period`

### `GET /api/groups/:groupId/settlement`

- 入力
  - パス: `groupId`
  - 認証 + グループ所属必須
- 成功出力（`200`）
  - `SettlementResult`
  - 主要項目:
    - `transactions[]`（誰が誰へいくら払うか）
    - `memberBalances[]`（メンバー別残高）
    - `totalExpenseAmount`
    - `expenseCount`

## 9.7 招待リンク

### `POST /api/groups/:groupId/invitations`

- 入力（JSON）
  - `expiresInDays?: number`（未指定時 7 日）
- 成功出力（`201`）
  - `{ id, token, url, expiresAt, createdAt, status }`
- 権限
  - `OWNER` / `ADMIN`

### `GET /api/groups/:groupId/invitations`

- 入力
  - パス: `groupId`
- 成功出力（`200`）
  - 有効招待リンクの配列

### `DELETE /api/groups/:groupId/invitations/:invitationId`

- 入力
  - パス: `groupId`, `invitationId`
- 成功出力（`200`）
  - `{ ok: true }`

### `GET /api/invite/:token`

- 入力
  - パス: `token`
- 成功出力（`200`）
  - `InvitationInfo`（`groupName`, `groupColor`, `memberCount`, `expiresAt` など）
- 代表エラー
  - `404`: 無効リンク
  - `410`: 期限切れ

### `POST /api/invite/:token/accept`

- 入力
  - パス: `token`
  - 認証必須
- 成功出力（`200`）
  - `{ groupId, groupName }`
- 挙動
  - 未参加なら `MEMBER` として追加
  - 既参加なら重複追加せず成功レスポンス
