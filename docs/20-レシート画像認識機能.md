# 20. レシート画像認識による支出自動登録機能

> 実装日: 2026-06-09  
> ブランチ: `10-feat-レシート画像認識による支出自動登録機能を追加`

---

## 概要

支出登録画面にレシート読み取りボタンを追加し、撮影 or 画像選択→AI 解析→フォーム自動入力までを 1 タップで完結させる機能。

ユーザーは金額・カテゴリ・メモを手入力する代わりにレシートを撮るだけで済み、入力の手間を大幅に削減できる。

---

## ユーザーフロー

```
支出登録画面
  └─ [レシート読取] ボタンをタップ
       ├─ スマートフォン: カメラが直接起動
       └─ PC: ファイル選択ダイアログが開く
            ↓
       画像を選択・撮影
            ↓
       フロントエンドで画像を圧縮（最大 1024px・JPEG 80%）
            ↓
       POST /api/receipt/analyze（base64 送信）
            ↓
       Claude Vision API で解析
            ↓
       合計金額・店名・カテゴリ推定を返却
            ↓
       フォームに自動入力（金額・ジャンル・メモ）
            ↓
       ユーザーが内容を確認・修正して [登録]
```

---

## 機能要件

### FR-1 画像入力
- 支出登録フォームの右上に **「レシート読取」ボタン**を配置
- `<input type="file" accept="image/*" capture="environment">` を使用
  - iOS / Android: カメラ起動を優先
  - PC: ファイル選択ダイアログ
- 選択後、圧縮した画像をフォーム上部に **プレビュー表示**（✕ で閉じられる）

### FR-2 画像圧縮
- Canvas API で最大 1024px にリサイズ
- JPEG 品質 0.8 で base64 化（API 転送量を抑制）
- 圧縮はブラウザ上で実行（サーバー負荷なし）

### FR-3 API エンドポイント
- **`POST /api/receipt/analyze`**
- 認証: JWT Bearer トークン必須（未認証は 401）
- リクエスト: `{ image: string }` ※base64 の data URL または raw base64
- レスポンス:

```ts
{
  amount: number | null,     // 合計金額（円）
  category: CategoryName | null,  // 推定カテゴリ
  memo: string | null,       // 店名
  confidence: "high" | "low" // 読み取り信頼度
}
```

### FR-4 AI 解析ロジック
- **モデル**: `claude-opus-4-8`（最高精度）
- Claude Vision に画像 + プロンプトを送信し JSON を受け取る
- 抽出項目:
  - 合計金額: 「合計」「お支払い」「TOTAL」の金額
  - 店名: レシートに記載の店名
  - confidence: 金額が明確に読み取れた場合 `high`、不確かな場合 `low`

### FR-5 カテゴリ自動推定
店名に含まれるキーワードでカテゴリをマッピング（サーバーサイドで処理）:

| キーワード例 | カテゴリ |
|------------|---------|
| スーパー・コンビニ・飲食・レストラン・カフェ | 食費 |
| 電車・バス・タクシー・高速・ガソリン | 交通 |
| 薬局・ドラッグストア・病院・クリニック | 医療 |
| ホームセンター・100円・日用品・洗剤 | 日用品 |
| 映画・ゲーム・カラオケ・娯楽 | 娯楽 |
| ドコモ・ソフトバンク・au・通信 | 通信 |
| 美容院・ヘアサロン・エステ・ネイル | 美容 |
| 書店・塾・スクール・教材 | 教育 |
| 家賃・電気・ガス・水道 | 住居 |
| 上記以外 | その他 |

### FR-6 フォーム自動入力
解析結果をフォームに反映する。ユーザーはすべてのフィールドを登録前に修正できる。

| 解析結果 | 対応フォーム項目 | null 時の挙動 |
|---------|----------------|------------|
| `amount` | 使った金額 | 空欄のまま |
| `category` | ジャンル | 空欄のまま |
| `memo` | メモ | 空欄のまま |

### FR-7 エラーハンドリング

| ケース | UI での挙動 |
|-------|-----------|
| 解析中 | ボタンをスピナーに変え、フォーム全体を `disabled` |
| `confidence: "low"` | ⚠️ トースト「読み取り精度が低い可能性があります。内容をご確認ください」 |
| `confidence: "high"` | ✅ トースト「レシートを読み取りました」 |
| 解析失敗（APIエラー） | ❌ トースト「レシートの読み取りに失敗しました。手入力してください」 |
| 画像がレシートでない | Claude が `amount: null` + `confidence: low` を返す → 上記と同様 |

## 技術的判断

### なぜ Claude Vision を使うのか
- 既存の OCR ライブラリ（Tesseract 等）は日本語レシートへの精度が低く、前処理も複雑
- Claude Vision はプロンプトで「何を抽出するか」を自然言語で指定でき、構造化 JSON を直接返せる
- スキーマ変更なしにサーバーサイドだけで完結する

### なぜ `claude-opus-4-8` を使うのか
- レシート画像の文字認識は鮮明さにばらつきがあり、高精度モデルが適切
- ユーザーが 1 回の登録につき 1 回しか呼ばない低頻度 API のためコスト影響は軽微

### なぜフロントで画像圧縮するのか
- モバイルカメラの画像は 5〜10MB になることがあり、そのまま送ると API タイムアウトのリスクがある
- Canvas API による圧縮は追加ライブラリ不要で実装できる

### なぜ `capture="environment"` を使うのか
- iOS/Android でカメラを起動する最もシンプルな方法
- ギャラリーからの選択もフォールバックとして機能するため UX を損なわない

### カテゴリ推定をサーバーサイドで行う理由
- フロントに推定ロジックを置くと、将来の変更がクライアントキャッシュに残る
- API レスポンスにカテゴリを含めることで、フロントはただ値をセットするだけになりシンプル
