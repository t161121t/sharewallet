# 20. レシート画像認識による支出自動登録機能

> 実装日: 2026-06-09  
> ブランチ: `10-feat-レシート画像認識による支出自動登録機能を追加`

---

## 概要

支出登録画面にレシート読み取りボタンを追加し、撮影 or 画像選択→OCR 解析→フォーム自動入力までを 1 タップで完結させる機能。

ユーザーは金額・カテゴリ・メモを手入力する代わりにレシートを撮るだけで済み、入力の手間を大幅に削減できる。

---

## ユーザーフロー

```
支出登録画面
  └─ [レシート読取] ボタンをタップ
       ├─ スマートフォン: カメラ or ギャラリー選択
       └─ PC: ファイル選択ダイアログが開く
            ↓
       画像を選択・撮影
            ↓
       フロントエンドで画像を圧縮（最大 1024px・JPEG 80%）
            ↓
       POST /api/receipt/analyze（base64 送信）
            ↓
       Google Cloud Vision API（DOCUMENT_TEXT_DETECTION）で OCR
            ↓
       テキストから合計金額・店名を正規表現で抽出
       店名キーワードでカテゴリを推定
            ↓
       フォームに自動入力（金額・ジャンル・メモ）
            ↓
       ユーザーが内容を確認・修正して [登録]
```

---

## コスト

Google Cloud Vision API の **DOCUMENT_TEXT_DETECTION** は月 **1,000 リクエストまで無料**。  
超過した場合は 1,000 リクエストあたり $1.50（2026年時点）。

小規模・個人利用であれば実質ゼロコストで運用可能。

---

## 機能要件

### FR-1 画像入力
- 支出登録フォームの右上に **「レシート読取」ボタン**を配置
- `<input type="file" accept="image/*">` を使用（`capture` 属性なし）
  - iOS / Android: カメラ or ギャラリーをユーザーが選択できる
  - PC: ファイル選択ダイアログ
- 選択後、圧縮した画像をフォーム上部に **プレビュー表示**（✕ で閉じられる）

### FR-2 画像圧縮
- Canvas API で最大 1024px にリサイズ
- JPEG 品質 0.8 で base64 化（API 転送量を抑制・上限 1.5MB を超えたら 413 を返す）
- 圧縮はブラウザ上で実行（サーバー負荷なし）

### FR-3 API エンドポイント
- **`POST /api/receipt/analyze`**
- 認証: JWT Bearer トークン必須（未認証は 401）
- リクエスト: `{ image: string }` ※base64 の data URL または raw base64
- レスポンス:

```ts
{
  amount: number | null,          // 合計金額（円）
  category: CategoryName | null,  // 推定カテゴリ
  memo: string | null,            // 店名（OCR テキストの先頭行）
  confidence: "high" | "low"      // 読み取り信頼度
}
```

### FR-4 OCR 解析ロジック
- Google Cloud Vision の `DOCUMENT_TEXT_DETECTION` で全文テキストを取得
- 金額抽出:
  1. **高信頼（confidence: high）**: 「合計」「お支払い」「お会計」「TOTAL」の直後の数値
  2. **低信頼（confidence: low）**: ¥ 付き金額の最大値をフォールバック
- 店名抽出: OCR テキストの先頭行（最初の意味ある行）
- タイムアウト: `AbortSignal.timeout(9000)` で 9 秒上限

### FR-5 カテゴリ自動推定
OCR 全文テキストに含まれるキーワードでカテゴリをマッピング（サーバーサイドで処理）:

| キーワード例 | カテゴリ |
|------------|---------|
| スーパー・コンビニ・飲食・レストラン・カフェ | 食費 |
| 電車・バス・タクシー・高速・ガソリン | 交通 |
| 薬局・ドラッグストア・病院・クリニック | 医療 |
| ホームセンター・100円・日用品・洗剤 | 日用品 |
| 映画・ゲーム・カラオケ・娯楽 | 娯楽 |
| ドコモ・ソフトバンク・au・通信 | 通信 |
| 美容院・ヘアサロン・エステ・ネイル | 美容 |
| 書店・塾・スクール・教材 | 教育 |
| 家賃・電気・ガス・水道 | 住居 |
| 上記以外 | その他 |

### FR-6 フォーム自動入力
解析結果をフォームに反映する。ユーザーはすべてのフィールドを登録前に修正できる。

| 解析結果 | 対応フォーム項目 | null 時の挙動 |
|---------|----------------|------------|
| `amount` | 使った金額 | 空欄のまま |
| `category` | ジャンル | 空欄のまま |
| `memo` | メモ | 空欄のまま |

### FR-7 エラーハンドリング

| ケース | UI での挙動 |
|-------|-----------|
| 解析中 | ボタンをスピナーに変え、フォーム全体を `disabled` |
| `confidence: "low"` | ⚠️ トースト「読み取り精度が低い可能性があります。内容をご確認ください」 |
| `confidence: "high"` | ✅ トースト「レシートを読み取りました」 |
| 画像サイズ超過 | ❌ 413 エラー |
| API エラー | ❌ トースト「レシートの読み取りに失敗しました。手入力してください」 |

## 環境変数

`.env` に以下を追加する必要があります:

```
GOOGLE_CLOUD_VISION_API_KEY="AIza..."
```

### API キーの取得手順

1. [Google Cloud Console](https://console.cloud.google.com) でプロジェクトを作成
2. **Cloud Vision API** を有効化
3. 「認証情報」→「API キーを作成」
4. API キーの制限: **Cloud Vision API** のみに絞ることを推奨
5. 取得したキーを `.env` の `GOOGLE_CLOUD_VISION_API_KEY` に設定

## 技術的判断

### なぜ Google Cloud Vision を使うのか
- **月 1,000 リクエスト無料** で小規模利用はほぼゼロコスト
- `DOCUMENT_TEXT_DETECTION` は日本語レシートに高い精度
- SDK 不要・REST API のみで実装でき依存ライブラリを増やさない
- Claude Vision（有料）と比べてコスト面で大幅に有利

### なぜ Claude Vision を使わないのか
- 毎リクエスト課金（入力トークン + 画像トークン）が発生する
- 月数百回の使用でも数百円〜数千円のコストになる可能性がある

### なぜフロントで画像圧縮するのか
- モバイルカメラの画像は 5〜10MB になることがあり、そのまま送ると API タイムアウトのリスクがある
- Canvas API による圧縮は追加ライブラリ不要で実装できる

### なぜ `capture` 属性を使わないのか
- `capture="environment"` はモバイルでギャラリー選択を妨げるブラウザがある
- 既存写真からのレシート登録ユースケースを残すため属性なしにした

### なぜ金額抽出を 2 段階にするのか
- 「合計」行を見つけた場合は信頼度高く、¥ の最大値はフォールバックとして信頼度低
- ユーザーに「この値は確認が必要」という情報を渡すことで誤登録を防ぐ
