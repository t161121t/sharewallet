# 32. CI 型チェック追加まとめ

## これは何のドキュメント？

[GitHub issue #28](https://github.com/t161121t/sharewallet/issues/28) で行った、GitHub Actions CI に `tsc --noEmit`(型チェック)ステップを追加した作業の記録です。

## まず結論（今回できたこと）

- `package.json` に `typecheck` スクリプト(`tsc --noEmit`)を追加した
- `.github/workflows/ci.yml` の `test-and-lint` ジョブに、テスト・リントより前段で型チェックを実行するステップを追加した
- 型エラーを含む PR は、テストやリントが通っても CI 全体が失敗するようになった

```bash
npm run typecheck
```

## 背景 — なぜこの変更が必要だったか

`.github/workflows/ci.yml` は `npm test`(Vitest)と `npm run lint`(ESLint)のみを実行しており、TypeScript の型チェックが含まれていなかった。ESLint は未使用変数など型に関連する一部の問題は検出できるが、型の不整合そのもの(例: 存在しないプロパティへのアクセス、関数の引数の型ミスマッチ)は検出できない。そのため、`npx tsc --noEmit` がローカルで実行されない限り、型エラーを含んだ変更がテスト・リントさえ通ればマージされてしまうリスクがあった。

このリポジトリではこれまでの実装(issue #19, #21, #22 対応など)でも、PRを出す前に手元で `npx tsc --noEmit` を毎回実行して確認する運用にしていたが、これを忘れた場合や、そもそもローカルで確認していないPRが来た場合に検出する手段がCIになかった。

## 目的

### 主目的

1. 型エラーを含むPRをCIで機械的に検出できるようにする
2. 実行順序をテスト・リントより前にし、型エラーがある場合は早く失敗させる(fail fast)

### あえてやらなかったこと

| やらなかったこと | 理由 |
| --- | --- |
| `next build` によるビルドチェックへの置き換え | ビルドは型チェック以外(バンドル、ページ生成など)も含み時間がかかる。今回は型チェックだけを素早く検証したいため `tsc --noEmit` に留めた |
| 型チェックを独立したjobに分離する | 現状のジョブ構成(`test-and-lint`という1ジョブ)を大きく変えると影響範囲が広がるため、既存ジョブにステップを1つ追加するだけの最小変更にした |

## 何を実装したか

### `package.json`

```diff
   "scripts": {
     "dev": "next dev --turbopack",
     "build": "next build --turbopack",
     "start": "next start",
     "lint": "eslint",
+    "typecheck": "tsc --noEmit",
     "test": "vitest run",
     "test:watch": "vitest"
   },
```

### `.github/workflows/ci.yml`

```diff
       - name: Generate Prisma Client
         run: npx prisma generate

+      - name: Run typecheck
+        run: npm run typecheck
+
       - name: Run tests
         run: npm test
```

`Generate Prisma Client`の直後、`Run tests`より前に配置した。Prismaのクライアント生成(型定義の生成)を先に済ませておかないと、`prisma.user`等の型が解決できず`tsc`が失敗するため、この順序が必須。

## よくある質問

### Q. なぜ`Generate Prisma Client`の直後に置いたの？

`tsc --noEmit`はPrismaが生成する型定義(`src/generated/prisma`)に依存しているため、生成前に実行すると型解決エラーで失敗する。既存の`Run tests`/`Run lint`も同じ理由でPrisma生成の後に置かれており、それに倣った。

### Q. ローカルの`npx tsc --noEmit`と`npm run typecheck`は何が違う？

同じコマンドをスクリプト化しただけで、実行内容は同一。今後CIやローカルで統一した呼び方ができるようにスクリプト化した。
